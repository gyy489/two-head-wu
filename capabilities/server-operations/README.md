# 私人静态站点发布能力包

这是两头乌中管理“4 台机器、2 个站点”的私人能力包。Codex 负责理解请求和完成网页；本能力包只提供
固定的发布边界。它不是通用服务器管理工具。

共享资源目录可以登记资料库等其它资源；本能力包按 `capability: server-operations` 所有权筛选，始终
只读取自己管理的 4 台机器，避免其它 Capability 的资源扩展改变发布边界。

## 你实际会得到的体验

在网页项目中对 Codex 说：

> 把这个网页部署到临时公开页面中。

在一次性安装好受保护执行器之后，Codex 会构建网页、检查静态输出，并把内容冻结到**已登记项目工作区**
的 `var/server-ops/`。固定本地客户端把这份冻结内容打包为常规 tar 文件描述符（FD），交给受保护
执行器；执行器只在自己的私有暂存区解包、上传、同步重试并检查 HTTPS 发布标记。无需输入 `--approve`，
无需逐次确认。

```text
Codex
  → 公开预检/冻结适配器（已登记项目工作区内的快照）
  → 仓库内 IPC 客户端（外部只收 publication_id；内部传 tar FD）
  → 仓库外、独立服务账户的受保护执行器（只解包到私有暂存）
  → 固定站点 → HTTPS 验证 → 项目报告
```

受保护执行器是确定性的“手”，不是第二个 Agent：它没有对话、不会自行选择目标，也只支持两个固定
静态站点。

## 当前状态

| 功能 | 状态 | 说明 |
|---|---|---|
| 查询 4 台机器和 2 个站点的脱敏信息 | 已开通 | 只显示 ID、角色和状态；不显示 IP、SSH、密码或路径。 |
| 预检本地静态目录 | 已开通 | 拒绝符号链接、`.env`、密钥、数据库导出、服务端脚本等。 |
| 冻结网页发布快照 | 已开通 | 原目录随后被修改也不会改变本次发布。 |
| 发布 IPC 协议、客户端、服务安装源码与本地模拟验收 | 已实现 | 客户端外部只收发布 ID，内部把冻结快照传为常规 tar FD；服务源码不是已安装服务，测试不接触真实服务器。 |
| 受保护执行器服务 | 未安装 | 必须在项目仓库外、独立服务账户下完成一次性安装。 |
| 真实两站上传 | 未开通 | 执行器未安装时客户端必须失败关闭，绝不回退到 SSH 或猜测配置。 |
| SSH / FRP / Nginx / HTTPS / DNS / 数据库 | 未开通 | 不属于当前静态站点能力包。 |

因此，本仓库目前包含的是协议、客户端、参考实现和模拟验证，**不是已安装的生产发布器**。一次性
安装与首次实发验收完成后，后续发布不需要人工确认。

## 无逐次确认的真实含义

这是一项一次性、严格限域的长期授权：获准访问固定本地 Socket 组的本机进程，可以为获准项目和站点
提交静态发布物，从而替换这两个固定站点的静态内容。执行器仍不会向它暴露 SSH 密钥、主机映射、任意
远程命令或其它服务器权限。

它**不能**从技术上证明某一次 IPC 请求一定源自某句自然语言或某次构建，也不能把文件黑名单当作通用
防泄漏系统。因此安装时必须只把 IPC Socket 组权限给可信本机工作流；不要把保险、身份资料或其它
私人目录作为构建输出。已登记项目工作区仅供不受保护的客户端寻找冻结快照，受保护服务不会打开或遍历
它。若未来需要“每一次必须由你亲自确认”，应另建确认型发布能力，而不是假装当前自动能力能提供这种证明。

## 两个站点

| 站点 ID | 说明 | 访问 | 发布含义 |
|---|---|---|---|
| `private-site` | 个人英文信息站 | 认证访问 | 替换已登记站点的静态内容。 |
| `public-site` | 对外信息分享站 | 公开、无自动下线 | 替换 `https://public.example/site/` 的静态内容。 |

`public-site` 不是“自动新建临时子站”的意思，而是一个长期存在、内容经常替换的固定公开站点。

## Codex 使用的两个命令

先确认当前项目拥有该能力：

```bash
core/bin/wu resolve --agent two-head-wu --runtime codex --project <project-id> --intent server-operations
```

随后 Skill 自动串联：

```bash
# 1. 预检并冻结当前网页；不联网
capabilities/server-operations/adapters/server-operations publish \
  --project <project-id> --site public-site --source <dist-or-build-directory>

# 2. 只传回上一步的 publication_id；向固定本地 IPC 服务提交发布
capabilities/server-operations/private-runner/site-publisher publish \
  --release <publication-id>
```

第二个命令是**客户端**，不接受主机、端口、远端路径、SSH 参数、密码、配置路径或 Socket 路径。它
对调用方只接受发布 ID；随后在已登记项目工作区找到对应的公开冻结快照，将其封装为常规 tar FD 并发往
固定的受保护本地 IPC 接口。受保护服务从不接收或打开项目路径；服务未安装或不可用时会安全失败。

## 受保护边界

实际执行器必须运行在与日常 Codex/Agent 不同的系统服务账户中，并且位于项目仓库外。该服务账户独占：

- 已登记项目的工作区登记信息、各项目获准的站点、两个固定站点的映射与验证规则；
- 专用部署身份及其最小 SSH 配置；
- 服务自身的上传暂存、单次发布状态和脱敏审计；
- 固定 Socket 及其受限的本地调用组。

公开适配器和仓库内客户端都不能读取这些资料，也不能把连接信息传给执行器。执行器验证请求和归档 FD
后，只把归档解包到自己控制的发布暂存区，再同步到受限的两个站点根目录。它不会打开或遍历 Agent
可写的项目目录，也不能获得交互式远程 shell。

逻辑私有资料仍可称为 `two-head-wu-private`，但用于真实发布的文件不能放在项目目录或任何可被普通
Agent 账户写入的位置。详情见[私有发布配置契约](references/private-site-publisher-contract.md)与
[受保护执行器](references/trusted-private-runner.md)。在 Mac 安装服务时，进一步遵循
[生产安装契约](references/production-installation.md)。

服务不需要、也不应获得各项目 `var/server-ops/` 的读取或遍历 ACL：快照由不受保护的客户端读取并通过
常规 tar FD 交付。服务必须使用独立账户，普通 Agent 账户都绝不能写服务的私有根目录；同样，Socket
组不能扩展给不受信任的本机程序。

## 自动重试的边界

每次已提交的发布在当前连接中**同步**最多尝试 4 次；每次上传总时限 5 分钟、失败间隔 5 秒，并且每次都要
经过 HTTPS 发布标记验证。客户端最多等待 30 分钟，因此不会在服务仍按此有界窗口运行时过早报告失败。它不是
跨夜常驻队列：4 次都失败时会返回失败状态，不会在后台无限继续。若未来要获得
跨夜重试、排队或定时发布，应另建有持久队列和监控的能力包。

完整静态暂存只在当前同步发布期间保留，结束后即删除；脱敏状态和审计最多保留 90 天，并限制总记录数，避免
Socket 组成员把服务私有磁盘当成归档仓库。

## 未来扩展

临时改域名、增加后端交互、部署服务、操作数据库或做 DNS 变更应各自成为新的能力包和受保护执行器。
Codex 可以组合它们，但不会通过当前静态发布能力获得任意 SSH 或服务器管理权限。
